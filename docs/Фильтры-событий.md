При установке фильтров будут регистрироваться в БД только события описанные в фильтрах.
Внутри фильтра все поля объединяются по «И», фильтры объединяются по «ИЛИ». Параметры фильтра совпадают с полями событий. Событие перед регистрацией в БД проходит через все фильтры до того, который его пропускает.
## Установка
```json
{
	"set":"event_filter",
	"event_filter" {
		"id":0,
		"allow":"true",
		"category":"0",
		"code":"11",
		"number":"1"
	}
}
```
## Запрос
```json
{
	"get":"event_filter",
	"event_filter":{}
}
```
## Ответ (результат выполнения set или ответ на get)
```json
{
	"answer":{"event_filter":"ok"},
	"event_filter":{
		"id":0,
		"allow":"true",
		"category":"0",
		"code":"11",
		"number":"1"
	}
}
```
`id` — уникальный номер фильтра, **int**

`allow` — пропуск события через фильтр (удовлетворяющее полям `category`, `code`, `number`), **строка** (для установки допустим **bool**):

		`true` - да
		`false` - нет 

`category` — категория события (соответствует категории, описанной в разделе События), **int**:

	0 - События, связанные с доступом по  идентификатору
	1 - События, связанные с доступом без идентификаторов
	3 - События, связанные с состояниями входов / выходов
	4 - События, связанные с функционированием
	5 - Сервисные события

`code` — код события (соответствует кодам, описанным в разделе События), **int**

`number` — номер ресурса (ИУ, ФК), **int**

Ошибки "error":

	"DB error" — ошибка записи в БД.
