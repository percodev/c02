Доступ через ИУ разделяется на два типа - персонифицированный (по карте), и не персонифицированный (по команде сервера системы / ПДУ).
Логика доступа на стороне контроллера реализована через механизм асинхронных событий доступа и обработку команд управления от сервера системы / ПДУ. Здесь важно не путать два типа асинхронных событий. Первый тип - это события формируемые контроллером по окончанию процесса (доступа), они содержат время, и регистрируются в БД (параллельлно с асинхронной передачей при соответствующих настройках фильтрации сокета (см. раздел События)). Второй тип - это события, формируемые контроллером (в том числе) в процессе (доступа). Такие события безусловно передаются по всем открытым сокетам для обработки их сервером системы, с последующей выдачей команды управления.

Т.о. персонифицированный доступ выглядит следующим образом:
- пользователь предъявляет карту, контроллер отправляет событие серверу {"event":"card","card":{"number":0,"direction":1,"id":"686409"}}
- сервер системы обрабатывает принятый id и даёт команду управления {"control":"exdev","exdev":{"number":0,"direction":1,"action":"open","open_type":"open once","open_time":7000}}
- контроллер отвечает серверу системы {"result":{"exdev":"ok","control":"own"},"exdev":{"number":0,"direction":1,"action":"open","open_type":"open once","open_time":7000}}
- контроллер разблокирует ИУ, и передаёт серверу системы событие разблокировки {"event":"exdev_unlock","exdev_unlock":{"number":0,"direction":1,"unlock":true}}
	- по истечению таймаута (не дождавшись прохода) контроллер блокирует ИУ и передаёт серверу системы события отказа от прохода {"event":"refusal_personal","refusal_personal":{"number":0,"direction":1,"id":"686409","command_source":"server","remove_card":false}} и разблокировки {"event":"exdev_unlock","exdev_unlock":{"number":0,"direction":1,"unlock":false}}
	- если проход состоялся (получен сигнал PASS), контроллер блокирует ИУ и передаёт серверу системы события персонифицированного прохода {"event":"pass_personal","pass_personal":{"number":0,"direction":1,"id":"686409","command_source":"server","remove_card":false}}, и после окончания сигнала PASS, разблокировки {"event":"exdev_unlock","exdev_unlock":{"number":0,"direction":1,"unlock":false}}

Не персонифицированный доступ выглядит следующим образом:
- сервер системы передаёт контроллеру команду управления ИУ {"control":"exdev","exdev":{"number":0,"direction":1,"action":"open","open_type":"open once","open_time":7000}}
- контроллер отвечает серверу системы {"result":{"exdev":"ok","control":"own"},"exdev":{"number":0,"direction":1,"action":"open","open_type":"open once","open_time":7000}}
- контроллер разблокирует ИУ, и передаёт серверу системы событие разблокировки {"event":"exdev_unlock","exdev_unlock":{"number":0,"direction":1,"unlock":true}}
	- по истечению таймаута (не дождавшись прохода) контроллер блокирует ИУ и передаёт серверу системы события отказа от прохода {"event":"refusal_impersonal","refusal_impersonal":{"number":0,"direction":1,"command_source":"server"}} и разблокировки {"event":"exdev_unlock","exdev_unlock":{"number":0,"direction":1,"unlock":false}}
	- если проход состоялся (получен сигнал PASS), контроллер блокирует ИУ и передаёт серверу системы события не персонифицированного прохода {"event":"pass_impersonal","pass_impersonal":{"number":0,"direction":1,"command_source":"server"}}, и после окончания сигнала PASS, разблокировки {"event":"exdev_unlock","exdev_unlock":{"number":0,"direction":1,"unlock":false}}

Управление внутренними реакциями на примере активизации / нормализации выходов:
- конфигурация {"set":"cref","cref":{"number":1,"source":"command","source_number":0,"source_direction":0,"destination":"activated output","destination_number":0,"destination_direction":0,"time_criteria":"absolute time","time_reaction":5000}}
- ответ на конфигурацию {"answer":{"cref":"ok","set":"own"},"cref":{"number":1,"source":"command","source_number":0,"source_direction":0,"destination":"activated output","destination_number":0,"destination_direction":0,"time_criteria":"absolute time","time_reaction":5000}}
- команда управления {"control" : "cref", "cref" : {"activate" : true, "number" : 1}}
- ответ на команду управления {"result":{"cref":"ok","control":"own"},"cref":{"activate":true,"number":1}}
- активация выхода, событие {"event":"output","output":{"function":"output","on":false,"number":0}}
- через 5 секунд (см. конфиг.) нормализация выхода, событие {"event":"output","output":{"function":"output","on":false,"number":0}}

# Установка РКД.
## Установка: сервер системы → контроллер
```json
{
	"control" : "acm",
	"acm" : {
		"number" :  0,
		"direction" :  0,
		"access_mode" : "open"
	}
}
```
## Ответ: контроллер → всем
```json
{
	"result" : { "acm": "ok" },
	"acm" : {
		"number" :  0,
		"direction" :  0,
		"access_mode" : "open"
	}
}
```
Номер ИУ `number`, **int** : 0 — 1

Номер направления ИУ `direction`, **int** : 0 — 1

Режим контроля доступа РКД `access_mode`, **строка** : 

			`open` — ОТКРЫТО
			`control` — КОНТРОЛЬ

# Открыть/закрыть ИУ

## Установка: сервер системы → контроллер
```json
{
	"control" : "exdev",
	"exdev" : {
		"number" :  0,
		"direction" : 0, 
		"action" : "open",
		"open_type" : "open once",
		"open_time" : 1000
	}
}
```
## Ответ: контроллер → всем
```json
{
	"result" : { "exdev": "ok" },
	"exdev" : {
		"number" :  0,
		"direction" : 0, 
		"action" : "open",
		"open_type" : "open once",
		"open_time" : 1000
	}
}
```

Номер ИУ `number`, **int** : 0 — 1

Номер направления ИУ `direction`, **int** : 0 — 1

Действие `action`, **строка** :

		`open` — разблокировать ИУ
		`close` — заблокировать ИУ

Тип разблокировки `open_type`, **строка** : 

		`open once` — открыть для однократного прохода
		`open oncealways` — открыть для однократного прохода с бесконечным ожиданием (прохода)
		`open once remove card` — открыть для однократного прохода с изъятием карты
		`open always` — открыть для многокрытных проходов (постоянно)

Время разблокировки, мс `open_time`, **int** : 100 - 1000000
